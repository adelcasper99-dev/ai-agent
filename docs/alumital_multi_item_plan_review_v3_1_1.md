# مراجعة v3.1 — باج حرج: الـ regex الجديد بقى ميمسكش حاجة خالص

## المشكلة الوحيدة (بس خطيرة)

الإصلاح اللي عملته لمشكلة "جدول/جهاز" استخدم `\b` (word boundary) حوالين الكلمات العربية:
```
\bجنيه\b | \bج\b(?:\s|$)
```

**المشكلة:** `\b` في JavaScript regex بيتحدد بناءً على `\w` (اللي معرّف افتراضياً كـ `[A-Za-z0-9_]` بس — مفيهوش حروف عربي خالص). يعني الانتقال من مسافة (non-word) لحرف عربي (برضه non-word في نظر JS) **مفيهوش boundary أصلاً**. النتيجة: `\bجنيه\b` عملياً **مش بيطابق أي حاجة** لو مسبوقة بمسافة، وده أغلب الحالات الطبيعية.

جربتها فعلياً في node:

| النص | المفروض يمسكه؟ | فعلياً بيمسكه؟ |
|---|---|---|
| "الإجمالي هيبقى حوالي 67000 **جنيه**" | ✅ أيوه | ❌ **لأ** |
| "السعر يبقى 3000 **ج.م**" | ✅ أيوه | ✅ أيوه (لأن ج.م مفيهاش `\b`) |
| "التكلفة 15000 **ج**" | ✅ أيوه | ❌ **لأ** |
| "شباك ألوميتال جديد في المخزن" | ❌ لأ (false positive قديم) | ❌ لأ (صح) |

يعني الإصلاح قفل الـ false-positive (كويس)، لكن كسر الحارس بالكامل تقريباً لأي هلوسة بترجع بكلمة "جنيه" أو "ج" لوحدها — وده أكتر صيغة متوقعة إن الـ LLM يستخدمها. الحارس دلوقتي شغال بس في حالة "ج.م" الأقل شيوعاً.

## الحل

امسح الـ `\b` خالص (مش موثوق فيه مع عربي في JS من غير `/u` وproperty escapes)، واستخدم lookahead صريح بدل منه:

```typescript
const freeTextPattern = /(?:مقايسة|شباك|باب|ألوميتال|الوميتال|المتر|أمتار|الأمتار).*(?:الإجمالي|التكلفة|السعر|الحسبة).*(?:\d{3,7}|\d+[\.,]\d+)\s*(?:جنيه(?!\S)|ج\.م(?!\S)|ج(?=\s|$)(?!دول|هاز|ديد|نب))/i;
```

جربتها بنفس أمثلتك القديمة (جدول/جهاز/جديد) + الحالات الصحيحة، وكلها طلعت صح:

| النص | النتيجة |
|---|---|
| "...الإجمالي هيبقى حوالي 67000 جنيه" | ✅ اتمسكت |
| "...السعر يبقى 3000 ج.م" | ✅ اتمسكت |
| "...التكلفة 15000 ج" | ✅ اتمسكت |
| "...شباك ألوميتال جديد في المخزن" | ❌ متمسكتش (صح) |
| "...والسعر تقريبا 500 جدول" | ❌ متمسكتش (صح) |
